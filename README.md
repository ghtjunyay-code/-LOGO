# ロゴ刺繍 見積もり依頼

本人確認用の試作です。既存プリントサイト・メール・顧客データとは独立しています。価格・納期・加工条件は業者が回答します。メール送信は未設定で、送信処理自体を実装していません。

## 使い方

1. 会社組織名 → ご担当者様名 → 電話番号 → LINE登録案内の順に入力します。最初の3項目は必須、メール登録は不要、LINE登録は任意です。プリント版と同じ店舗LINEのQRコードを使用します（ユーザー確認済み）。
2. 商品情報は任意です。未定の場合は省略して刺繍情報へ進めます。サイズと数量を入力する場合は両方をそろえ、同じ商品の同サイズは一行にまとめます。
3. 刺繍する箇所、ロゴ、寸法、希望糸色、型データの有無を指定します。商品未指定でもロゴ刺繍の依頼は可能です。
4. 必要に応じて受け取り希望日を指定します。依頼書には希望日と暦日5日前の両日を記載します。空欄なら確認日程は追加しません。
5. 内容を確認して履歴に保存します。依頼書から日本語・原稿・寸法入りPDFを作成し、保存できます。対応端末では共有も可能です。

商品コピーは管理番号を引き継ぎ、サイズと数量を空欄にします。刺繍内容も含むコピーと、商品情報だけのコピーを選べます。履歴の再注文は元の記録を残したまま新しいIDで開き、納期と確認チェックをリセットします。

下書きは自動保存と手動保存があります。ネットワーク障害時は入力を保持し、画面で保存失敗を表示します。ブラウザの一時下書きと原稿のローカル保持に加え、サイト専用D1/R2に再編集データと原本を保存します。アップロード未完了の原稿は同じ端末で再試行できます。

## 開発・保存先

Node.js 24以上とpnpmを使用します。`pnpm dev`、`pnpm build`、`node --test tests/quote.test.mjs tests/storage.test.mjs`（APIテストはlocalhost:3000が必要）、`node tests/pdf-check.mjs`、`pnpm exec tsc --noEmit`。

DB変更はDrizzleスキーマと生成マイグレーションで管理。ローカル初回は `pnpm exec wrangler d1 execute site-creator-d1 --local --file drizzle/0000_careless_surge.sql --config wrangler.local.json` を実行します。公開済みマイグレーションを書き換えないこと。

`.openai/hosting.json` の既存project_idを再利用します。Sitesのアクセス制御は本人限定を維持し、一般公開は別途確認が必要です。認証情報はソースに保存しません。

日本語フォントは [Noto Sans JP](https://github.com/google/fonts/tree/main/ofl/notosansjp) のwght=400を固定化したものです。SIL Open Font License 1.1（public/fonts/OFL.txt）。元のvariableフォントをfontToolsで静的TrueTypeに変換しました。PDFはpdf-libとfontkitを利用します。
